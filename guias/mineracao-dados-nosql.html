Módulo 1 — O que é mineração de dados

TEORIA

1.1 Explicação

A mineração de dados (data mining) é o processo de descobrir padrões, relações e tendências ocultas em grandes conjuntos de dados. É a ponte entre armazenar dados e extrair valor deles.

A ideia central

Imagine que você tem milhões de registros de compras. Sem mineração, é só um mar de números. Com ela, descobre-se, por exemplo, que quem compra fraldas tende a comprar cerveja — um padrão não óbvio que pode orientar promoções.

1.2 As quatro tarefas principais

TarefaO que fazExemplo
Classificaçãoprevê uma categoria discreta.e-mail é spam ou não?
Agrupamento (clustering)descobre grupos naturais sem rótulos.segmentar clientes
Regras de associaçãoencontra co-ocorrências.itens comprados juntos
Detecção de anomaliasidentifica o que foge do padrão.fraude em transações
Classificação vs. agrupamento

Na classificação, você já conhece as categorias (rótulos) e ensina o modelo a reconhecer. No agrupamento, você não sabe os grupos — o algoritmo os descobre. Essa distinção é central.

Módulo 2 — Classificação

CÓDIGO

2.1 Explicação

Na classificação, o objetivo é atribuir um rótulo a um novo registro, com base em exemplos rotulados. É um problema de aprendizado supervisionado: os dados de treino já trazem a resposta.

2.2 Prática em Python

PYTHON — classificando flores (Iris) com scikit-learn
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.neighbors import KNeighborsClassifier
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)
X_treino, X_teste, y_treino, y_teste = train_test_split(
    X, y, test_size=0.3, random_state=42)

modelo = KNeighborsClassifier(n_neighbors=3)
modelo.fit(X_treino, y_treino)
pred = modelo.predict(X_teste)

print("Acurácia:", accuracy_score(y_teste, pred))
O conjunto Iris é o clássico da área. train_test_split separa treino e teste — passo essencial para avaliar se o modelo generaliza.
O erro mais comum

Medir o desempenho nos próprios dados de treino dá uma falsa impressão de acerto (isso é sobreajuste). Sempre avalie em um conjunto não visto — por isso a separação treino/teste e a validação cruzada.

Módulo 3 — Agrupamento e regras de associação

CÓDIGO

3.1 Agrupamento (clustering)

O K-Means é o algoritmo de agrupamento mais usado: separa os dados em K grupos com base na similaridade, sem que você informe os grupos.

PYTHON — agrupando com K-Means
from sklearn.cluster import KMeans
import numpy as np

X = np.array([[# suas features], [# ...]])
modelo = KMeans(n_clusters=3, random_state=0, n_init=10)
modelo.fit(X)

print("Centroides:", modelo.cluster_centers_)
print("Grupos:", modelo.labels_)
Como escolher K

O número de grupos (K) não é óbvio. A técnica do cotovelo (elbow method) compara a inércia do modelo para diferentes K e ajuda a escolher o ponto de equilíbrio. Depois, você interpreta cada grupo — é aí que o conhecimento do domínio entra.

3.2 Regras de associação

As regras de associação respondem "quais itens aparecem juntos?". O algoritmo clássico é o Apriori, que gera regras do tipo A → B, com métricas de suporte (frequência) e confiança (certeza).

PYTHON — associação entre produtos
from mlxtend.frequent_patterns import apriori, association_rules
import pandas as pd

# Matriz de transações: 1 = item presente, 0 = ausente
df = pd.read_csv("transacoes.csv")   # colunas = produtos

frequentes = apriori(df, min_support=0.05, use_colnames=True)
regras = association_rules(frequentes, metric="confidence", min_threshold=0.6)
print(regras[["antecedents", "consequents", "support", "confidence"]])
Exemplo de saída: fraldas → cerveja com confiança 0,7 significa que, quando as fraldas são compradas, a cerveja acompanha em 70% das vezes. É o célebre exemplo de análise de cesta de compras!

Módulo 4 — Detecção de anomalias

CÓDIGO

4.1 Explicação

A detecção de anomalias identifica registros que fogem significativamente do padrão. É usada em detecção de fraude, monitoramento de mau funcionamento e segurança. Entre os métodos está o One-Class SVM e técnicas estatísticas (como z-score).

PYTHON — anomalias com z-score
import numpy as np
import pandas as pd

df = pd.DataFrame({"valor": [10, 12, 11, 13, 12, 11, 12, 900, 12, 11]})
media, desvio = df["valor"].mean(), df["valor"].std()
df["z"] = (df["valor"] - media) / desvio

# pontos com |z| > 3 são atípicos
anomalias = df[df["z"].abs() > 3]
print(anomalias)
O valor 900 destoa claramente. O z-score quantifica "o quanto" ele se afasta — uma maneira rápida de flagrar possíveis erros ou fraudes antes de investigar cada caso.

Módulo 5 — Bancos NoSQL

PRÁTICA

5.1 Explicação

Quando os dados são muito variados, muito volumosos ou precisam de alta escala, o modelo relacional pode não bastar. Os bancos NoSQL ("Not Only SQL") sacrificam parte do rigor relacional em favor de flexibilidade e escalabilidade.

O teorema CAP

Em sistemas distribuídos, um banco precisaria escolher um subconjunto de três garantias: consistência (C), disponibilidade (A) e tolerância a partições (P). Na prática, dado que falhas de rede ocorrem (P), a escolha é entre priorizar C ou A. Isso explica a diversidade dos bancos NoSQL.

5.2 Os principais tipos

1. Bancos de documentos
Armazenam dados em documentos (JSON), com desnormalização controlada (embedding). Ex.: MongoDB, CouchDB, Amazon DocumentDB. Uso: dados flexíveis, catálogos de produtos.
2. Chave-valor
O modelo mais simples: cada registro é um par chave → valor. Ex.: Redis (em memória, mais de 100 mil ops/seg.), DynamoDB, Riak. Uso: cache, sessões, contadores em tempo real.
3. Colunares (column-family)
Organizam os dados por coluna em vez de linha, otimizando compressão e consultas que acessam poucas colunas. Ex.: Apache Cassandra, HBase. Uso: análise em grandes volumes, séries temporais.
4. Grafos
Modelam entidades e relações como nós e arestas. Ex.: Neo4j. Uso: redes sociais, detecção de fraudes em cadeias de relacionamentos.

5.3 Escolhendo entre relacional e NoSQL

SituaçãoRecomendação
Dados estruturados, consultas complexas, transaçõesRelacional (SQL)
Dados flexíveis, formato variadoDocumentos (MongoDB)
Leitura/escrita muito rápida por chaveChave-valor (Redis)
Análise em escala e poucas colunasColunar (Cassandra)
Relações intensas entre entidadesGrafos (Neo4j)
Arquitetura poliglota

Não é preciso escolher um único banco. Muitas organizações combinam SQL (para transações) com NoSQL (para escala e variedade), formando uma arquitetura poliglota.

5.4 Checklist

  • Distingo classificação, agrupamento, associação e anomalias
  • Sei a diferença entre aprendizado supervisionado e não supervisionado
  • Rodei uma classificação com scikit-learn
  • Entendo o que são suporte e confiança em associação
  • Conheço os 4 tipos de bancos NoSQL
  • Entendo o teorema CAP
Consideração final

Mineração de dados é problema primeiro, algoritmo depois. Antes de aplicar um modelo, pergunte-se: que tipo de conhecimento estou buscando? E, quando o volume e a forma dos dados exigirem, saiba que o NoSQL oferece a flexibilidade que o modelo relacional nem sempre comporta.
