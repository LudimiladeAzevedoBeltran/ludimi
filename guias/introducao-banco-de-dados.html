Módulo 1 — O modelo relacional

TEORIA

1.1 Explicação

O modelo relacional, proposto por Edgar F. Codd (1970), organiza os dados em tabelas (chamadas formalmente de relações). Cada tabela é um conjunto de linhas (registros) e colunas (atributos).

A ideia central

Imagine uma planilha: cada linha é um registro (um aluno, um produto), cada coluna é um atributo (nome, nota, preço). O relacionável transforma essa intuição em uma estrutura rígida e consistente, com regras matemáticas bem definidas (a álgebra relacional).

1.2 Fundamentação teórica

ConceitoSignificado
Relação (tabela)conjunto de registros com estrutura definida.
Atributo (coluna)característica que descreve os registros.
Tupla (linha)um registro individual.
Chave primária (PK)atributo (ou conjunto) que identifica de forma única cada linha.
Chave estrangeira (FK)referência à chave primária de outra tabela, criando relacionamentos.
Entidadeobjeto do mundo real que se deseja representar (Aluno, Disciplina).
Por que o modelo relacional domina

Ele oferece integridade (regras que impedem dados inconsistentes), flexibilidade (consultas ad-hoc) e isolamento entre os dados. O SQL (Structured Query Language) é a linguagem padrão de operação sobre esses bancos.

Módulo 2 — Entidades, relacionamentos e o DER

TEORIA

2.1 Explicação

Antes de criar tabelas, é necessário modelar o mundo real. O Diagrama de Entidades e Relacionamentos (DER) é a ferramenta que representa as entidades e como elas se associam.

2.2 Fundamentação teórica

ElementoDescriçãoExemplo
Entidadeobjeto com existência própria.Aluno, Disciplina, Curso
Atributouma propriedade da entidade.Nome, CPF, CargaHoraria
Relacionamentoassociação entre entidades.Aluno está matriculado em Disciplina
Cardinalidadequantos registros se relacionam.1:N, N:M, 1:1

2.3 Tipos de relacionamento

1:N — Um para muitos
Um registro de A liga-se a vários de B. Ex.: um Curso possui várias Disciplinas.
N:M — Muitos para muitos
Vários A ligam-se a vários B. Ex.: um Aluno cursa várias Disciplinas e cada Disciplina tem vários Alunos. Resolve-se com uma tabela intermediária (ex.: Matrícula).
1:1 — Um para um
Cada registro de A liga-se a um único de B. Ex.: uma Pessoa possui um Passaporte.

2.4 Estudo de caso — sistema acadêmico

Para um sistema de ensino, identificam-se entidades como Aluno, Professor, Curso, Disciplina, Turma e Matrícula. A relação Aluno : Disciplina é N:M, materializada pela entidade associativa Matrícula, que pode guardar atributos próprios (data de matrícula, situação).

Armadilha comum na modelagem

Confundir entidade com atributo é frequente. "Telefone" deve ser atributo da entidade Cliente — a menos que precise existir de forma independente. Modelar demais ou de menos compromete a qualidade do banco.

Módulo 3 — Normalização: reduzindo a redundância

PRÁTICA

3.1 Explicação

A redundância (mesma informação em vários lugares) gera inconsistência: basta atualizar uma cópia e esquecer a outra. A normalização é o processo que organiza as tabelas para minimizar esse problema, aplicando formas normais progressivas.

O problema da redundância

Se o endereço de um professor está na tabela de professores e também na de funcionários, uma mudança de endereço exige atualizar os dois lugares. Se apenas um for alterado, o banco passa a conter informações contraditórias. Normalizar evita exatamente isso.

3.2 As formas normais

FormaRegra principal
1FNatributos atômicos; sem grupos repetitivos (cada célula, um valor).
2FNalém da 1FN, atributos não-chave dependem de toda a chave (não de parte dela).
3FNalém da 2FN, nenhum atributo não-chave depende de outro atributo não-chave (sem dependência transitiva).
BCNFrefina a 3FN: todo determinante é chave candidata.
Equilíbrio: quando desnormalizar

Em data warehouses e sistemas de leitura intensa, a desnormalização (redundância deliberada) é válida para acelerar consultas. O segredo é escolher com consciência — e garantir a consistência por outros meios (ETL, triggers).

3.3 Prática — normalização passo a passo

Vejamos uma tabela desorganizada e como a normalização a decompõe:

CÓDIGO — detectando problemas com pandas (1FN)
import pandas as pd

# Tabela "desnormalizada": um aluno com várias disciplinas na mesma linha
df = pd.DataFrame({
    "aluno": ["Ana", "Ana"],
    "disciplinas": ["Matemática, Física", "Estatística"],
    "nota": [9.0, 8.5]
})
df
Violação da 1FN: a célula "disciplinas" contém múltiplos valores. Devemos separar cada disciplina em seu próprio registro.

Módulo 4 — SQL: consultando os dados

CÓDIGO

4.1 Explicação

O SQL é a linguagem declarativa com a qual você diz o que quer obter, e não como fazer. É a ponte entre o modelo e o resultado.

SQL — criar uma tabela
CREATE TABLE aluno (
    matricula INT PRIMARY KEY,
    nome       TEXT NOT NULL,
    cpf        TEXT UNIQUE,
    curso      TEXT
);
SQL — consultar com JOIN
-- aluno (matricula, nome) ; matricula_disciplina (matricula, codigo, nota)
SELECT a.nome, d.nome, m.nota
FROM aluno a
JOIN matricula_disciplina m ON a.matricula = m.matricula
JOIN disciplina d ON m.codigo = d.codigo
WHERE d.nome = "Estatística";
O JOIN combina tabelas por chaves (chave estrangeira). É a operação mais usada em consultas relacionais.

4.2 As operações da álgebra relacional

OperaçãoO que faz
Seleção (σ)filtra linhas (WHERE).
Projeção (π)escolhe colunas (SELECT).
Junção (⋈)combina tabelas (JOIN).
União (∪)reúne registros de tabelas semelhantes (UNION).

Módulo 5 — Python na prática: sqlite3 e pandas

CÓDIGO

Você trabalha com Python — então nada melhor do que aplicar tudo isso resolvendo um problema real. O módulo sqlite3 (embutido no Python) permite criar um banco relacional de verdade no seu computador.

5.1 Criando e populando o banco

PYTHON — criar tabelas e inserir dados
import sqlite3

con = sqlite3.connect("academico.db")
cur = con.cursor()

cur.execute("""CREATE TABLE IF NOT EXISTS aluno (
    matricula INTEGER PRIMARY KEY,
    nome TEXT NOT NULL,
    curso TEXT
)""")

cur.execute("INSERT INTO aluno VALUES (?, ?, ?)", (1, "Ana Silva", "Estatística"))
cur.execute("INSERT INTO aluno VALUES (?, ?, ?)", (2, "Bruno Costa", "Computação"))
con.commit(); con.close()

5.2 Consultando com Python e pandas

PYTHON — seleção e projeção via pandas
import pandas as pd
import sqlite3

con = sqlite3.connect("academico.db")

# Projeção + seleção: colunas escolhidas, linhas filtradas
df = pd.read_sql_query(
    "SELECT nome, curso FROM aluno WHERE curso = ?", con,
    params=("Estatística",)
)
print(df)
con.close()
Com pandas, o resultado do SQL já vira um DataFrame — pronto para análise e visualização. É a ponte entre o banco relacional e a ciência de dados.
